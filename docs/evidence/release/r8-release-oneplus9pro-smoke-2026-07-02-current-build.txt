Purpose
-------

Verify the temporary-signed R8 release APK on a physical OnePlus 9 Pro CN after
fixing the release UI lookup path for the real current build.

This is private-trial packaging and real-device UI smoke evidence. It is not a
public release readiness claim.

Root Cause Summary
------------------

The release UI initially showed:

    查询失败
    未知错误。

Two separate causes were found and fixed:

1. A true current-build ColorOS component request returns HTTP 200 with
   `responseCode=2004` and `errMsg=artifactV1Result is empty`. This means no
   update artifact is available for the current build and should map to
   `NoUpdate`, not a server failure.
2. The app called synchronous OkHttp `execute()` from a ViewModel coroutine on
   the main dispatcher. Android treats that as main-thread networking, which was
   caught as a runtime error and surfaced as Unknown. The transport now switches
   the blocking HTTP call to `Dispatchers.IO`.

Known Limits
------------

- This current-build query intentionally returns `NoUpdate`; the live endpoint
  does not return the current full package for a profile that is already on that
  build.
- The current-version full ZIP itself was already downloaded and verified on
  local disk in
  `docs/evidence/download/current-full-package-oneplus9pro-cn-2026-07-02.txt`.
- The successful package-found chain still uses the guarded replay profile from
  `docs/evidence/ota/live-coloros-oneplus9pro-cn-2026-07-02.txt`.
